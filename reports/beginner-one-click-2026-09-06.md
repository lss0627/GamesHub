# 小白一键启动与真实流程验收（2026-09-06）

本轮沿用 SpecKit 004，围绕 Windows 本地创作，不改变当前单人 2D 猫咪跑酷的产品范围。HTTP 后端为 FastAPI；Unity 与已有领域 Worker 通过 stdio 接入。

## 用户入口

双击项目根目录的 `启动GamerHub.cmd`（或 `Start-GamerHub.cmd`）。启动器按顺序准备 Docker、Python 服务依赖、Unity/WebGL、存储、数据库和创作页面；重复启动复用已有进程。Node.js 24+、pnpm、Docker Desktop 和 uv 为首次安装的基础工具，缺失时有明确提示。

Unity 工程创建、素材导入/绑定、测试和网页导出随“确认说明，开始制作”自动执行。无需日常手动打开 Unity。首次下载或补齐 Unity/WebGL 复用固定版本官方安装脚本；本机组件已安装，本轮验证了检测复用，未为测试而删除并重装约 5GB 的编辑器。本人登录 Unity Hub、许可激活及 Windows 授权仍需本人完成。页面明确区分组件检测与实际构建许可验证。

## 审视发现与修复

| 原问题 | 处理结果 |
| --- | --- |
| 启动需要多条命令，小白容易遗漏后台 | 双击入口、自动顺序启动、隐藏后台、日志与可重试提示 |
| 重复启动可能创建重复服务或遇到端口冲突 | 启动互斥、识别服务身份、复用已运行服务；不结束未知进程 |
| PostgreSQL 容器启动后还未接受连接，迁移失败 | Compose 等待健康检查后才迁移，真实冷启动复验 |
| Next 构建继承开发环境导致预渲染报错 | 前端构建和运行明确 production，后台保留本地开发配置 |
| 缺少 Unity 会让整个 RPC 后台初始化失败 | 延迟引擎初始化；读项目和对话保持可用，制作准入返回中文可处理的 503 |
| “Unity 已就绪”此前为固定值 | 检测编辑器、WebGL 与模板，模型状态只称已配置，不虚报连接/许可成功 |
| 环境异常没有可理解的下一步 | 创作页中文准备状态、独立轮询、手动重试；聊天与制作按能力分别控制 |
| 已完成试玩依赖编辑器初始化 | WebGL 读取独立于制作引擎，缺 Unity 仍能访问已发布产物 |
| 美术清单模型输出偶发截断，变成 INTERNAL_ERROR | 提高完整清单输出预算；只对无效结构最多重试一次，持续失败返回可理解的素材清单错误，供应商故障不盲目重试 |
| 旧容量页展示固定实时指标 | 改为真实准备状态，去除假实时容量数据 |

本机还实际遇到 Docker Desktop 自身残留通信文件引发的启动崩溃。停机后仅将两个临时通信目录改名备份，随后成功启动；没有删除项目、容器卷或执行出厂重置。现象与 [Docker 官方仓库问题记录](https://github.com/docker/desktop-feedback/issues/448) 相符。此机器修复未扩张成启动器中的自动删除逻辑。
