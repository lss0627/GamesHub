# Agent 日常使用优化验收 · 2026-09-26

本轮完善素材任务恢复、输入安全和启动效率。最新前后端已在本机启用，`http://127.0.0.1:3000` 可使用。既有项目与已发布试玩保留。

## 已实现

1. **逐张进度与显式续跑**：显示已保存 `n/8`、当前角色和配色。每张图片绑定写入 PostgreSQL；失败、停止或服务重启后，可继续剩余部分，保留原始描述和已验证的素材清单。执行令牌隔离迟到结果，修订号阻止并发覆盖，未完成图片组不进入可选候选。
2. **恢复的边界检查**：待完成素材同样校验归属、哈希和审核状态。Provider/端点/模型/质量变化后阻止混合续跑，密钥轮换可继续；已保存八张、只差最后发布时无需生图服务。上传成功后断点临时保存失败，会尝试保存已有结果，不自动重新调用模型。
3. **按项目保存草稿**：输入文字和来源保存在当前浏览器，刷新后恢复。初始 GET 不覆盖刚输入的文字；切换项目后忽略旧请求结果，并重置旧操作锁和版本号。
4. **减少后台请求**：生成时 2.5 秒轮询，空闲时 10 秒轮询，隐藏页面暂停，返回立即刷新；单页不重叠发送轮询。
5. **启动反馈和构建复用**：后台子进程提前退出时立即报告对应日志。构建缓存同时验证源码、依赖/配置/环境输入和生产输出摘要；失败或缺文件不复用。保留仍存活且被复用的服务进程记录。

## 使用和限制

- 失败后选择“继续上次准备”跳过已提交到断点的图片；选择“按当前描述重新准备两组”开启新任务。
- 草稿只存于当前浏览器；断点存于数据库，跨浏览器/后端重启可读取。旧项目没有断点时仍正常展示候选，但不能补造旧任务的恢复进度。
- 外部模型超时、连接中断或进程在上传与断点提交之间退出，可能存在已计费但未确认的请求。显式恢复这些图片仍可能再次计费；系统不承诺远端服务 exactly-once 计费。
- 当前外部生图仍未配置，使用内置素材；图片适配器已有自动化契约验证，真实供应商连通、画质和费用需配置后验收。
- Python 测试保留两项既有 Starlette/httpx 弃用警告；不影响本轮结果。

配置、恢复接口和复现命令见 [Agent 开发手册](../docs/runbooks/agent-development.md)。
