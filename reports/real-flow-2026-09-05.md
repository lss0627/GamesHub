## 本轮实际修复

1. game-planner、evaluator 和 platform-api 缺少工作区依赖声明，TypeScript/Vitest 别名掩盖了真实 Node 启动错误。补齐 package.json 和 lockfile，新增原生 Node 导入服务入口回归。
2. 健康检查仍只要求前 8 个迁移，可能错误接受旧数据库。已要求第 009 号迁移，旧 8 迁移状态必须返回未就绪。
3. 真实预览资源被 COEP 拦截。不可变预览路由新增匿名 CORS 与 CORP 响应头，并增加响应头契约断言。
4. Unity 的 Cache Storage 在 opaque-origin 沙箱中抛错。只对与 Studio 不同来源的 HTTP(S) 预览允许其保留自身来源，供 Unity 缓存使用；同源或非 HTTP(S) URL 仍使用严格沙箱，并增加安全回归。
5. 建立专用真实流程测试和恢复验证脚本，分别保存业务记录、数据库证据和浏览器场景。

## 复现

日常开发使用 `pnpm dev`，会先启动基础设施和执行迁移，再启动本地服务及 Studio。当前配置为 real-unity、postgres-redis、DeepSeek。

在服务运行时执行一次全新的真实验收（会调用模型和 Unity）：

```powershell
$env:GAMERHUB_REAL_FLOW='1'
pnpm exec playwright test --config playwright.flow.config.ts
pnpm exec tsx scripts/verify-real-cycle.ts
pnpm exec tsx scripts/inspect-flow-preview.ts
```

专用验收脚本测试固定的 4 → 6 → 4 场景，记录写入上述目录；不要把它当作任意项目数据的通用检查工具。`GAMERHUB_FLOW_PROJECT_ID` 只用于续接刚完成创建的该场景，默认应不设置。普通 `pnpm test` 不会触发模型付费调用。
