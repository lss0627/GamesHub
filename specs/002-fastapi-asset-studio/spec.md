# Feature Specification: 完整创作项目的后端迁移与自动素材工作室

**Feature Branch**: 无 Git 仓库；特性目录 `002-fastapi-asset-studio`
**Created**: 2026-09-06
**Status**: Implemented and validated locally; see reports/fastapi-art-studio-2026-09-06.md
**Input**: 用户要求用 SpecKit 负责打通「讨论画风 → AI 整理素材清单 → 自动准备候选素材 → 用户确认或要求修改 → 自动导入 Unity、绑定角色和场景 → 重新试玩」，并将完整项目后端由 Fastify 迁移为 FastAPI。

## User Scenarios & Testing

### User Story 1 - 原有项目在迁移后继续工作 (Priority: P1)
创作者打开原有项目，继续聊天、查看 Spec、上传素材、制作、查看任务诊断、试玩、修改与恢复版本。
**Why this priority**: 后端替换必须保留现有数据和行为。
**Independent Test**: 通过浏览器前端访问迁移后的服务，检查旧项目与新建项目；契约检查状态码、错误、事件、图片和试玩响应。
**Acceptance Scenarios**:
1. Given 已有对话和可玩版本，When 切换服务并刷新，Then 项目、历史对话、素材和旧试玩仍可使用。
2. Given 缺少权限或请求不合法，When 请求接口，Then 返回可读且一致的错误，不泄露内部路径和秘密。
3. Given AI 延迟或服务重启，When 用户重试，Then 保留输入，确认重试不重复制作。

### User Story 2 - 系统准备完整美术候选 (Priority: P1)
小白描述画风，系统根据玩法整理角色、背景、收集物和障碍物需求，并提供至少两组成套候选。无需用户自行搜索或上传文件。
**Why this priority**: 消除找素材这一核心门槛。
**Independent Test**: 无上传文件、无图片生成密钥时，仍可获得、预览和保存完整的内置候选；有生成服务时可显式选择该来源。
**Acceptance Scenarios**:
1. Given 已有游戏方案，When 用户描述温暖森林或夜色风格并请求候选，Then 展示对应需求清单、至少两组完整候选、来源与使用范围。
2. Given 某组候选不合适，When 用户修改描述重新准备，Then 新旧候选可以区分，已发布版本不变。
3. Given 外部生成未配置或失败，When 请求该来源，Then 提示真实原因并允许选择内置候选，不伪称生成成功。

### User Story 3 - 确认素材后真实应用并试玩 (Priority: P1)
用户选择一组素材，审阅包含素材清单的 Spec，明确确认制作；角色和场景使用选中的内容。
**Why this priority**: 素材预览必须与游戏中实际使用一致。
**Independent Test**: 完成一次真实构建，核对选中素材、确认 Spec、导入内容哈希与游戏截图；换组制作后恢复旧版。
**Acceptance Scenarios**:
1. Given 完整候选，When 选中但未确认制作，Then 仅更新草案，不创建制作任务。
2. Given 用户确认素材和 Spec，When 制作成功，Then 四类素材均导入并绑定，显示当前游戏实际采用的素材。
3. Given 制作失败，When 重新打开项目，Then 仍可试玩上一成功版本，失败候选不能标为已应用。
4. Given 两个不同素材版本，When 恢复旧版，Then 试玩和已应用素材信息共同恢复。

### User Story 4 - 新手可以理解并持续修改 (Priority: P2)
界面解释「候选」「已选」「当前游戏使用」的区别；保留对话引导、素材进度、错误恢复和玩法说明。
**Independent Test**: 桌面和手机完成选择、确认与返回试玩；刷新不丢选择。
**Acceptance Scenarios**:
1. Given 首次创作，When 打开素材面板，Then 自动准备是主要入口，自备素材上传为可选入口。
2. Given 任务正在制作，When 修改候选或确认，Then 防止覆盖制作中的快照，完成后可以继续打磨。

### Edge Cases
- 陈旧 revision、重复请求、重复点击、跨项目素材引用、缺失角色、无效图片或哈希不一致。
- 候选生成超时、中途取消、外部供应商不可用、重启后仍有未完成候选任务。
- 编译失败、旧版本恢复、旧项目没有素材计划、模型提出当前模板不支持的画风或主题。
- 图片超限、未知来源 URL、路径穿越、未授权素材、过期候选确认。

## Requirements

### Functional Requirements
- **FR-001**: 保留项目、任务、版本、事件、素材与对话现有对外能力和持久化数据。
- **FR-002**: 聊天与素材选择不隐式开始制作；确认提交完整且不可变的方案快照。
- **FR-003**: 自动整理四个必要素材角色；候选包含名称、用途、来源、预览、内容指纹与版本。
- **FR-004**: 无外部生成配置时仍提供至少两组完整可用的内置候选，禁止冒称 AI 生成。
- **FR-005**: 支持配置图片生成来源；错误保留草稿且不产生虚假候选。
- **FR-006**: 支持改述画风重新准备、选择候选、将选择纳入制作说明。
- **FR-007**: 导入必须检查项目归属、图片有效性与内容指纹；绑定后接受真实引擎编译与试玩检查。
- **FR-008**: 仅成功发布后显示已应用，恢复版本同时恢复实际素材绑定。
- **FR-009**: 所有新状态持久化并具备 revision 并发保护；刷新、重启不丢已确认信息。
- **FR-010**: 保留图片上传入口，但完整主流程不要求上传任何文件。
- **FR-011**: 为迁移契约、素材状态、绑定与真实浏览器链路补充先失败后通过的回归测试。
- **FR-012**: 更新启动、环境示例、健康检查、架构说明与项目级验收记录，明确实际运行组件。

### Key Entities
- **ArtPlan**: 项目美术需求、描述、四类角色、版本、候选列表和选中候选。
- **ArtCandidate**: 成套素材、来源、风格、角色到素材的映射、不可变内容指纹。
- **GameSpec**: 确认的玩法和美术绑定快照。
- **AssetBinding**: 游戏角色、素材内容、引擎目标位置和引入版本。
- **Run/Build/Version**: 继续复用已有任务、检查证据、构建与版本记录。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 无用户上传情况下，浏览器完成画风描述、候选预览、选择、确认、制作、试玩全链路。
- **SC-002**: 每组候选四类素材齐全，选中内容与成功游戏使用内容逐一一致。
- **SC-003**: 两组不同候选完成制作与恢复验收，旧数据不丢失。
- **SC-004**: 未确认不执行、陈旧版本不覆盖、失败不标成功、跨项目引用被拒绝的用例全部通过。
- **SC-005**: 已有前端核心流程及迁移契约回归通过；运行入口可重复启动并显示真实依赖状态。

## Assumptions
- 继续以现有单人 2D 跑酷作为完整可执行游戏类型，扩展素材来源和风格，不承诺任意游戏类型已实现。
- 用户明确要求 FastAPI；具体语言边界和迁移方案写入 plan.md。
- 现有可复用的 Unity 执行器及领域逻辑可保留，运行中的 HTTP 后端不依赖 Fastify。
- 图片生成服务由本地配置提供；默认内置候选完整可用，外部生成能力单独标示可用性。
- 本轮为用户已授权的本地项目实施，不改变商业部署或 Unity 许可范围。
