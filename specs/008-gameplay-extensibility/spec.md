# Feature Specification: 持续扩展的游戏制作

**Feature**: 008-gameplay-extensibility
**Created**: 2026-09-08
**Status**: Approved scope from project-owner audit implementation request
**Input**: 可以，按照这个审视架构进行整体的项目优化。

## User Scenarios & Testing

### User Story 1 - 保留项目创作并安全更新基础能力 (Priority: P1)

创作者新增或修改玩法后，多轮制作不丢失项目代码和资源；基础更新有明确冲突信息与恢复方式。

**Independent Test**: 修改项目脚本，执行两轮制作和一次基础更新，比较内容，再恢复先前版本。

**Acceptance Scenarios**:
1. Given 项目修改了基础脚本，When 再次制作，Then 修改保留，冲突不会被静默覆盖。
2. Given 未修改的旧基础文件，When 基础更新，Then 自动升级且记录来源版本。
3. Given 旧项目缺少来源记录，When 首次升级，Then 保留未知来源的本地差异并提供诊断。

### User Story 2 - 按明确机制开发并验证游戏 (Priority: P1)

系统区分已有能力、待开发能力和不支持的能力，在已授权制作范围内完成机制开发和验证。

**Independent Test**: 要求一个需要项目代码的机制，观察开发步骤、文件变更、验证结果及下一轮保留结果。

**Acceptance Scenarios**:
1. Given 已确认的机制需求，When 开始制作，Then 能在正常制作阶段读取项目、编辑玩法并运行验证。
2. Given 未实现机制或无效参数，When 检查制作说明，Then 说明缺口，不静默忽略或转换类型。
3. Given 开发失败，When 重试或取消，Then 有检查点和诊断，未通过验收不能显示成功。

### User Story 3 - 已有玩法有可靠操作与明确规则 (Priority: P2)

已有四类游戏具有匹配操作、可读名称、暂停和稳定结算规则，射击与幸存者具有不同体验。

**Independent Test**: 键盘和触屏完成开始、暂停、胜负、重试；验证射击瞄准和点击成长截止收益。

**Acceptance Scenarios**:
1. Given 中文项目名称，When 启动，Then 显示该名称且可读。
2. Given 暂停或截止状态，When 时间推进或继续操作，Then 不发生无效状态变化和收益。
3. Given 射击场景，When 改变瞄准方向，Then 投射物和命中结果相应变化。

### User Story 4 - 更多具体 2D 类型形成完整流程 (Priority: P2)

可制作飞行躲避、打砖块、平台跳跃、塔防、具体解谜和对话冒险，每种都有对应操作和目标。

**Independent Test**: 每种预设从设计到预览，验证至少一个成功和失败或重置场景。

**Acceptance Scenarios**:
1. Given 任一具体预设，When 生成，Then 执行独有规则并显示对应操作与胜负条件。
2. Given 自定义创意，When 需求超出组合能力，Then 列明缺口并进入明确开发流程或说明限制。

### Edge Cases

- 本地和基础同名文件同时变化、首次迁移、重复同步、恢复旧版本。
- 重复或停用系统、未知字段、越界数值、不支持的组合。
- 开发阶段取消、工具超时、路径穿越和重试。
- 大时间步、暂停输入、胜利后重复触发、窄屏、长中文标题。

## Requirements

### Functional Requirements

- **FR-001**: 保留项目修改；基础升级仅替换确认未修改文件，冲突可追踪。
- **FR-002**: 项目恢复包含玩法文件和基础来源记录。
- **FR-003**: 登记机制输入、配置、兼容约束和验收要求，类型作为明确组合。
- **FR-004**: 未知或无效配置产生明确缺口；所有支持字段落实到游戏行为。
- **FR-005**: 正常制作允许明确的玩法开发任务，遵循现有隔离、检查点、取消和验证约束。
- **FR-006**: 未通过实际验证的开发结果不得宣告制作成功。
- **FR-007**: 修复四类已有玩法的时间边界、暂停、名称与触屏操作，并提供射击瞄准和投射物。
- **FR-008**: 新增飞行躲避、打砖块、平台跳跃、塔防、推箱子解谜、分支对话冒险六种具体预设。
- **FR-009**: 创作者能看到可执行、需要开发和尚不支持的能力信息。
- **FR-010**: 先失败后通过的测试覆盖契约、隔离、恢复和新机制，保存真实操作证据。

### Key Entities

- 基础版本记录：来源、文件指纹、迁移差异与冲突。
- 机制定义：标识、版本、配置、输入、依赖和验收义务。
- 机制开发任务：确认需求、上下文、变更与验证证据。
- 玩法预设：机制组合、操作说明、目标和内容。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 修改后连续两轮制作保留 100% 项目差异；恢复旧版本内容一致。
- **SC-002**: 未知字段、重复系统和越界输入用例全部明确拒绝，不静默降级。
- **SC-003**: 一个需要新代码的需求通过正常开发阶段、测试和真实预览，二次制作保留机制。
- **SC-004**: 十种具体预设均有独立规则、操作和完整流程验证记录。
- **SC-005**: 已有四种通过暂停、重试、时间边界检查，中文标题和触屏可用。

## Assumptions

- 默认按审视报告推进 2D；3D、联机、开放世界另行确定技术与验收阶段。
- 解谜采用推箱子，对话 RPG 采用分支对话冒险。
- 复用现有基础设施、项目记忆和检查点；保护原项目已发布作品。
- 授权包括实现、修复和本地验证，不包含公开商业发布。
