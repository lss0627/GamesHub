# Feature Specification: Python 托管真实 Pi Agent

**Created**: 2026-09-07
**Status**: Ready for planning
**Input**: 用户要求先接通 Pi Agent，使用 Python，删除旧冗余实现，优化 Agent 各链路，并将 CLI 作为工具调用。

## User Scenarios & Testing

### US1 真实设计伙伴与开发执行 (P1)
用户继续多轮讨论并确认制作说明；实际运行使用指定的开源 Agent 框架，展示真实工具进度，不以自写替身或模型 API 冒充框架。
独立验收：真实模型完成一次工具调用，工具结果进入下一轮；网页确认后生成可玩的 Unity 版本。

### US2 工具驱动的编辑与修复 (P1)
制作伙伴能读取当前工程、修改允许的游戏代码、调用编译与测试，将错误用于后续修复；用户无需复制终端命令。执行范围局限于当前项目。
独立验收：故意引入一个编译错误，Agent 读取诊断、修复文件、重新检查通过；越界路径与未注册命令被拒绝。

### US3 可恢复、可解释的迁移 (P1)
保留项目、历史版本、素材、确认与停止能力；旧的未接通适配器被删除，实际架构和启动状态明确。
独立验收：取消释放子进程，恢复不重复已完成的副作用；旧项目可读、可试玩；启动失败不回退到假实现。

### Edge Cases
模型断流/空结果、子进程退出、工具超时、无效参数、越界/链接路径、并发与租户、暂停取消、确认过期、编译修复预算耗尽、恢复过程中重复请求、旧版本无Agent记录。

## Requirements
- FR-001 实际使用官方 Pi Agent 循环，锁定版本并提供运行证据；无默认测试替身回退。
- FR-002 使用 Python 管理 Agent 生命周期、工具执行边界、事件与恢复；官方框架必须的最小宿主可以保留原语言。
- FR-003 讨论与制作分离，保留已确认Spec、租户及版本语义。
- FR-004 CLI 可注册为结构化工具，返回退出状态、输出、超时及证据；不把原始 shell 文本直接交给主机执行。
- FR-005 工程读取/编辑和编译诊断可进入同一Agent循环，至少验证一次真实自动修复。
- FR-006 停止、预算、异常和中断有明确状态；已完成副作用可恢复且不重复。
- FR-007 删除被替换且无生产用途的 Pi/DeepSeek占位实现、错误配置和重复入口；保留仍承载数据/Unity能力的代码直到有等效实现。
- FR-008 前端显示真实框架状态、工具进度和面向小白的错误指导，文档与运行一致。

## Key Entities
Agent会话、消息、工具定义、调用、结果、检查点、预算、确认Spec、运行证据。

## Success Criteria
- SC-001 已安装官方框架的真实会话完成工具→结果→后续推理，并记录版本与事件。
- SC-002 一次真实工程错误经过诊断和编辑后重新编译通过，保留前后证据。
- SC-003 创作台完成讨论→确认→制作→试玩，原有项目数据与已发布版本仍可访问。
- SC-004 越界工具、重复调用、超时取消及进程故障的回归通过；没有静默降级成功。

## Assumptions
优先使用既有DeepSeek模型与本机Unity；Pi官方核心是Node包，因此Python通过最小进程桥使用真实框架，不另写Python仿制品。前端仍为Next.js，现有领域和Unity适配能力按实际引用保留，冗余定义以替换完成且无用途为依据。此轮不承诺任意商业游戏自动完成。
