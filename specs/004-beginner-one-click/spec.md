# Feature Specification: 小白一键启动与就绪引导
**Feature**: 004-beginner-one-click（无Git分支）
**Created**: 2026-09-06
**Status**: Implemented and verified
**Input**: 启动整个项目、跑通所有既有流程，审视不合理之处并优化，面向小白，Unity最好一键集成。

## User Scenarios & Testing
### US1 一次操作进入创作 (P1)
小白点击一个入口，系统自动准备可自动完成的依赖并进入页面。
独立验收：关闭服务后启动成功；再次启动复用已有服务，不重复启动引擎工作进程。
1. 已安装基础工具，其他服务关闭时，自动准备环境并打开创作页。
2. 缺少引擎组件时进入已有安装流程；需要账户登录、许可激活或系统授权时明确解释，不虚报就绪。
3. 端口被其他程序占用或启动失败时，保留日志并给出下一步，不停止未知进程。

### US2 知道能做什么与下一步 (P1)
小白无需阅读技术诊断，能知道环境是否可用及如何处理阻塞。
独立验收：正常、断连、引擎缺失与模型未配置时呈现相应引导，不把连接中或模拟运行显示为真实制作可用。
1. 正常环境允许创作，问题状态给出中文原因和明确入口。
2. 普通创作界面不要求用户阅读原始引擎配置或日志。

### US3 从新想法到持续打磨 (P1)
多轮讨论后确认方案，准备素材、制作、试玩、调整与恢复。
独立验收：新项目制作、素材替换、暂停/继续、停止、修改和恢复经过自动化及真实运行验证。

## Requirements
- FR-001 提供Windows双击启动入口，按依赖顺序检查、准备、启动并等待服务可用。
- FR-002 自动检测并复用已有引擎与网页导出组件，缺失时复用固定版本安装入口；保留已有密钥及配置。
- FR-003 重复启动不会重复创建后台服务；未知端口占用明确失败且不杀进程。
- FR-004 显示真实就绪状态及中文处理建议，区分连接中、阻塞与可创作。
- FR-005 启动与创作错误可恢复，保留已有项目和试玩，不把安装成功等同构建成功。
- FR-006 验证所有既有创作故事，记录发现、修复、自动化结果和真实游戏证据。

## Key Entities
启动阶段、服务探测结果、创作就绪状态、既有项目/运行/素材/版本。

## Edge Cases
冷启动、重复点击、已有服务、未知端口、Docker未运行、引擎组件缺失、依赖安装、网络失败、缺少模型密钥、许可问题、UI重连。

## Success Criteria
- SC-001 已具备基础工具的本机通过一次操作进入创作页面，重复启动不增加服务数量。
- SC-002 就绪异常与恢复的关键回归通过；不存在虚假成功状态。
- SC-003 新项目创作、素材更换、暂停续跑、试玩、修改和恢复真实验证通过，停止安全性回归通过。
- SC-004 小白凭一份短说明再次启动，知道必须本人完成的登录/许可步骤。

## Assumptions
本轮Windows本地运行；Node.js、包管理器和Docker Desktop缺失时提供指引，已安装的Docker自动启动。Unity安装和工程/素材导入尽量自动；不代替本人登录或接受许可。保留单人2D Runner和既有模型配置，不扩张任意游戏能力。
