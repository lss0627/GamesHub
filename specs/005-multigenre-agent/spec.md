# Feature: 多类型游戏设计与可扩展执行
Created: 2026-09-06
Status: Ready for planning
用户要求：垂直游戏Agent支持多种游戏设计，不将幸存者想法改为跑酷，解释底层架构。
## User Scenarios & Testing
### US1 保留创意的设计伙伴 (P1)
讨论不同类型、玩法、主题和成长，不强制替换跑酷。多轮确认后看制作说明，类型和参数刷新保留。问题性描述不擅自改变现有方案。
### US2 真正制作新的玩法 (P1)
幸存者：俯视移动、追踪敌人、自动攻击、经验、升级选择、生命、倒计时胜负、重玩。俯视射击复用战斗能力，点击成长验证另一类玩法。旧跑酷可制作/恢复。
### US3 理解能力与架构 (P1)
页面展示相应类型、操作、目标和素材用途。未实现类型保留设计并列出执行缺口，不偷偷降级。架构文档解释设计、任务、工具、执行、验收和存储。
## Requirements
- FR-001 多类型设计与各自参数，兼容旧文档。
- FR-002 对话不固定拒绝战斗，不写入未同意的替代。
- FR-003 设计、准入、规划与执行共享能力定义，执行前报告缺口。
- FR-004 幸存者战斗升级闭环可玩；点击成长和旧跑酷保持独立玩法。
- FR-005 按Spec规划和选择运行时，验证对应行为，不以canvas代替玩法成功。
- FR-006 前端/Spec展示对应指南、素材用途与真实来源。
- FR-007 保持确认后制作、租户隔离、恢复与暂停停止边界。
- FR-008 提供与代码一致的架构图、职责和扩展方式。
## Key Entities
游戏类型、设计草案、玩法参数、能力描述、已确认Spec、任务图、运行、验收证据。
## Edge Cases
旧文档、类型切换、只提问不改动、不支持类型、非法参数、模型异常、素材适配、版本恢复、制作中修改。
## Success Criteria
- SC-001 幸存者多轮讨论后真实制作试玩，不变成跑酷。
- SC-002 新玩法有独立行为断言，升级影响数值，旧Runner回归通过。
- SC-003 未实现类型可讨论/保存/查看设计并明确缺口，无伪成功。
- SC-004 能力定义、指南与运行一致，架构可追溯。
## Assumptions
本机Unity2D/WebGL与现有模型基础设施。开放设计、可注册能力模块，首批上述3组运行时。不声称本轮完成所有游戏类型或商业级《吸血鬼幸存者》，不自动执行未经用户确认的设计。
