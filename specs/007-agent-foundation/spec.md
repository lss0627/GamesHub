# Feature Specification: 可持续工作的游戏创作伙伴
**Created**: 2026-09-08
**Status**: Ready for planning
**Input**: 用户要求下一步优化成熟Agent架构，重点上下文、记忆和工具系统。

## User Scenarios & Testing
### US1 记住项目并允许纠正 (P1)
长讨论或服务重启后继续创作，伙伴仍能找到项目约束和已确认方案；用户能查看、纠正、删除项目记忆，项目间互不混淆。
验收：40轮讨论后仍使用明确保存的约束；重启保持，修订/删除影响下一次会话，另一项目无法读取。
### US2 有边界的工具执行 (P1)
确认任务后伙伴使用适合当前阶段的工具，参数错误可纠正，失败保留证据并有限重试。工具文字不能代替验收。
验收：参数错误、未知工具、阶段越权、重复、超时取消均有明确结果；已有制作正常通过。
### US3 长任务的上下文依据 (P1)
执行时知道目标、已确认方案、相关记忆、已完成步骤和最近失败；长日志不淹没当前任务。用户能看到采用的记忆与工具摘要。
验收：超长历史/日志受预算控制，保留当前任务、确认要求和完整工具交互；恢复不重复已完成修改。
### Edge Cases
并发修订、会话中删除记忆、失效Spec来源、模型编造记忆、资料中的指令注入、跨项目读取、过大日志、孤立工具消息、预算不足、未知工具、中断副作用、旧项目无记忆。

## Requirements
- FR-001 记忆具有来源、类别、状态、修订和时间，区分用户记录、已确认方案、执行事实；推测不能成为已确认事实。
- FR-002 用户能查看、新增、纠正、删除项目记忆；旧摘要不能让删除信息自动复活。
- FR-003 按任务检索有界相关记忆，优先当前要求与已确认方案；过期来源不作为当前事实。
- FR-004 历史和工具输出有明确预算，保留完整交互组和可追溯历史摘要/引用；不将私有推理作为用户记忆。
- FR-005 工具统一描述输入约束、阶段、影响类别、超时、输出上限和结果，调用前独立校验和授权。
- FR-006 失败、重复、中断、取消、重试有统一状态与证据，不盲目重复未知副作用。
- FR-007 保留确认、版本、素材、停止恢复和制作流程；接入生产并清除被替换的重复逻辑。
- FR-008 前端简单中文解释项目记忆、本次依据和工具阶段；不展示路径、凭证、私有推理。
- FR-009 保留规划、执行、验证的扩展边界；尚无实现/验证的玩法不标为可制作。

## Key Entities
项目记忆、来源引用、记忆修订、上下文包、历史交互组、工具定义/结果、检查点、任务计划与证据。
## Success Criteria
- SC-001 40轮讨论与重启后可用保存约束；修订/删除影响后续会话，跨项目访问被拒绝。
- SC-002 历史日志超预算时保留当前要求和完整工具组，引用可追踪。
- SC-003 工具校验/权限/恢复回归及真实现有游戏制作试玩通过。
- SC-004 用户在页面完成记忆查看/修订/删除，代码文档与实际状态一致。
## Assumptions
沿用当前本地单用户、多项目部署与已接通框架，先做可靠项目内记忆和可插拔检索，不默认跨项目共享或外部记忆服务。不承诺本轮完成任意规模游戏；不恢复此前外部重置删除的数据库历史。
